## 0. 结论摘要

1. **版本与规模**：`OpenWrt 24.10.5 r8181-27d57f45e`，base-files 127，内核 **6.18.55**（2026-10-11 05:45:45 构建，`runner@runnervmwvtoz`），LuCI 26.159，**451 个包**，SquashFS 102.79 MiB，p2 为 **1 GiB**，overlay 可用约 **921 MiB**。
2. **仍是 Lean 风格定制**：`99-default-settings` 会把 release 改成 `LEDE R26.10.11`，仍用 firewall3 + iptables（不是 fw4），仍设置默认 root 密码、Tencent 镜像、关闭 opkg 签名校验。
3. **默认网络相同**：LAN **192.168.1.253/24**（eth0），WAN eth1 DHCP（存在时），DHCP 池 `.100–.249`，DHCPv6/RA，failsafe 仍是 192.168.1.1。
4. **登录与 6 月构建同样弱**：镜像内 root 密码为空，首次启动写入 `password` 的 MD5；`ttylogin=0`，串口/本地 tty 直接 root shell。
5. **默认开启的服务更多**：dropbear（22，**不再限制 LAN**）、uhttpd（80/443）、dnsmasq、odhcpd、NTP、TurboACC、**ttyd（7681，LAN）**、nlbwmon，以及 wsdd2/umdns/usbmuxd/arpbind 等启动项。**默认关闭**：Passwall、Passwall Server、OpenClash、ksmbd、ZeroTier、MIA、DDNS 示例。

7. **OpenClash 仍是“装了但没内核”**：`luci-app-openclash 0.48.002`，`enable=0`，`/etc/openclash/core/` 为空。
8. **安全面比 6 月构建更宽**：ttyd 默认开启、dropbear 监听所有接口、UPnP 相关包/启动项存在、Passwall 默认 `dns_redirect=1`/`prefer_nft=1`（一旦启用会接管 DNS/防火墙）；镜像尾部 GPT 备份表同样缺失。

## 5. 登录、SSH、LuCI

### 5.1 root 密码

- 当前 `/etc/shadow`：`root:::0:99999:7:::`（空）。
- 首次启动 `99-default-settings` 写入：
  ```
  root:$1$V4UetPzk$CYXluq4wUazHjmCDBCqXF.:0:0:99999:7:::
  ```
- 明文是 **`password`**（与 6 月构建相同）。必须首次登录后改。

### 5.2 dropbear

- `/etc/config/dropbear`：
  ```
  config dropbear main
      option enable '1'
      option PasswordAuth 'on'
      option RootPasswordAuth 'on'
      option Port '22'
  ```
- **没有 `Interface 'lan'`**：dropbear 默认监听所有接口（0.0.0.0/::）；WAN 侧仍被防火墙 input REJECT 挡住，但不再是“仅 LAN”。
- 无 `/root/.ssh/authorized_keys`；host key 首次启动生成。
- `50-dropbear` 会在 board.json 有 `credentials.ssh_authorized_keys` 时自动写入公钥并关闭密码登录；该镜像没有这些凭据。

### 5.3 LuCI / uhttpd

- uhttpd：`0.0.0.0:80`、`[::]:80`、`0.0.0.0:443`、`[::]:443`；`redirect_https=0`；`rfc1918_filter=1`。
- 证书 `/etc/uhttpd.crt/key` 不存在，首次启动用 OpenSSL 生成（EC P-256、730 天、CN=OpenWrt）。
- `luci`：`lang auto`、session 3600 秒；首次启动 `90_luci-theme-argon` 设 Argon 主题。
- `rpcd`：`login.username=root`、`login.password=$p$root`。
- 首次启动 `luci-app-passwall` 把 `uhttpd.main.max_requests` 从 3 改为 50。

## 7. SS / 代理能力（本构建的重点）

### 7.1 已安装的组件

| 组件 | 版本 | 作用 |
|---|---|---|
| `luci-app-passwall` | 26.10.4-1 | Passwall 客户端 + 服务端 UI |
| `shadowsocks-rust-ssserver` | 1.25.0-3 | `/usr/bin/ssserver`，SS 服务端 |
| `shadowsocks-rust-sslocal` | 1.25.0-3 | `/usr/bin/sslocal`，SS 客户端 |
| `sing-box` | 1.14.3-1 | `/usr/bin/sing-box`，Passwall/其他后端 |
| `luci-app-openclash` | 0.48.002 | OpenClash，默认关闭，core 为空 |

- **没有** `ssserver-luci` 这个独立 LuCI 应用；**没有** `shadowsocks-libev`；**没有** xray/hysteria/trojan 二进制（Passwall 默认配置里引用了 `/usr/bin/xray`、`/usr/bin/hysteria`，但镜像里没装，相关节点类型不可用）。
- Passwall 默认配置来自 `/usr/share/passwall/0_default_config`，首次启动复制到 `/etc/config/passwall`：
  - `global.enabled=0`
  - `dns_redirect=1`、`dns_shunt=chinadns-ng`、`dns_mode=tcp`、`remote_dns=1.1.1.1`
  - `tcp_proxy_way=redirect`、`prefer_nft=1` 等
  - `global_app` 指向 `/usr/bin/sing-box`、`/usr/bin/xray`、`/usr/bin/hysteria`
- `/etc/config/passwall_server` 只有：
  ```
  config global 'global'
      option enable '0'
      option start_delay '90'
  ```
  即 **Passwall Server 默认关闭，且没有任何 server 节点**。`S99passwall_server` 会 sleep 90 秒后调用 `server_app.lua start`，但 `enable=0` 时不会起服务。
- `passwall` 客户端同理：`S99passwall` 存在，但配置 `enabled=0`。

### 7.2 想在本机构建 SS 服务端

当前镜像**具备** `ssserver` 二进制和 Passwall 服务端 UI，但没有默认节点。可行路径：

1. 在 LuCI → Passwall → 服务端（Passwall Server）添加一个 Shadowsocks 节点，选择协议/加密/端口/密码；
2. 或在 `/etc/config/passwall_server` 里手工加 `config server` 段并 `enable 1`；
3. 防火墙放行该端口（默认 WAN input REJECT，需要新建 traffic rule）；
4. 若要独立 `ssserver-luci` 而不是 Passwall，需要自己编译/安装 `ssserver-luci` 包（当前镜像没有），并注意它与 Passwall Server 的端口/进程冲突；
5. 不建议直接 `opkg update && opkg upgrade`（见第 9 节）。

> 注意：Passwall 默认 `dns_redirect=1`、`prefer_nft=1`。一旦启用客户端，它会接管 DNS/防火墙；`prefer_nft=1` 但镜像里只有 `kmod-nft-*`、没有 nft 用户态命令，实际可能回退到 iptables。启用前先确认当前 fw3 规则和 DNS 行为。

## 10. 风险与建议

### 10.1 高优先级

| 风险 | 说明 | 建议 |
|---|---|---|
| 弱默认密码 | 首次启动后 root/password；MD5-crypt | 首次登录立即 `passwd`；不要暴露 22/80/443/7681 到 WAN |
| 串口免密 root | `ttylogin=0` | `uci set system.@system[0].ttylogin='1'`；`uci commit system` |
| ttyd 默认开 | `@lan:7681`，`/bin/login`，无 TLS/credential | 不用就 `/etc/init.d/ttyd disable; stop`；要用就加 `credential`/`ssl` |
| dropbear 监听所有接口 | 配置没有 `Interface 'lan'` | 加 `option Interface 'lan'` 或 `DirectInterface`；限制来源 |
| opkg 签名关闭/源错配 | 首次启动删除 `check_signature`，域名改 Tencent | 不要直接 upgrade；需要装包时手工修 feed/恢复签名 |
| GPT 备份表缺失 | 写盘后 `fdisk` 会警告 | 写盘后 `sgdisk -e`；大于 1.13 GiB 的盘先扩容 p2 |

### 10.2 中优先级

| 风险 | 说明 | 建议 |
|---|---|---|
| Passwall 默认 `dns_redirect=1` | 启用后会接管 DNS/防火墙 | 启用前确认 DNS 方案；不需要 DNS 劫持时改为 0 |
| `prefer_nft=1` 但无 nft 用户态 | 可能回退 iptables，行为不确定 | 确认实际规则；必要时在 Passwall 里改为 iptables |
| UPnP/`miniupnpd` | 启动项/包在，配置缺失；一旦启用会在 WAN 开 UPnP | 不用就禁用；要用就限制 internal/external 接口和 ACL |
| FullCone NAT 2 | TurboACC 默认高性能 FullCone | 不需要时 `turboacc.config.fullcone_nat=0` |
| HTTP 管理 | `redirect_https=0` | `uhttpd.main.redirect_https=1`；或只开管理 VLAN |
| `passwall_server` 默认关 | 有 ssserver 但没节点 | 需要 SS 服务端时在 Passwall Server 里添加节点并放行端口 |
| 旧 Argon 主题 | 1.8.4 与 LuCI 26.159 可能有 UI 兼容问题 | 异常时回退 bootstrap |

### 10.3 低优先级

| 项 | 说明 |
|---|---|

## 13. WireGuard 支持情况

### 13.1 原生内核 / LuCI WireGuard：默认不支持

- 没有 `kmod-wireguard`；`lib/modules/6.18.55/modules.builtin` 和 `modules.dep` 中都没有 `wireguard`，说明内核没有把 WireGuard 编进去/编成模块。
- 没有 `wireguard-tools`，即没有 `wg` 命令；没有 `wireguard-go`。
- 没有 `luci-proto-wireguard`（只有 `luci-proto-ipv6`、`luci-proto-ppp`），所以 LuCI 的“网络 → 接口 → 协议”里不会出现 WireGuard。
- 因此 **不能按标准 OpenWrt 方式** 在 `/etc/config/network` 里建 `proto wireguard` 接口，也不能直接 `ip link add wg0 type wireguard`。
- OpenClash core 为空，Clash Meta 的 WireGuard outbound 也无法使用。

### 13.2 Passwall + sing-box 用户态 WireGuard：支持

- 镜像自带 `sing-box 1.14.3`，实际运行 `sing-box version` 输出：
  ```
  Tags: with_acme,with_clash_api,with_gvisor,with_quic,with_tailscale,with_utls,with_wireguard
  ```
  即带 **`with_wireguard`**。
- Passwall 的 `sing-box` 节点类型在 `singbox_tags:find("with_wireguard")` 时显示 WireGuard 选项：
  - **客户端**：协议选 `WireGuard`，填写服务器公钥、客户端私钥、PSK、Local Address、MTU、Reserved；
  - **服务端**：协议选 `WireGuard`，填写私钥/公钥、Local Address、MTU，支持“Generate key”按钮生成密钥对；`wireguard_system_interface` 默认 `0`（用户态），设为 `1` 才会尝试系统内核接口。
- 默认 `passwall` 和 `passwall_server` 都是关闭的（`enabled/enable=0`），且没有任何节点；需要先启用并添加节点：
  - 客户端：LuCI → Passwall → 节点列表 → 添加 → 类型 `sing-box` → 协议 `WireGuard`；
  - 服务端：LuCI → Passwall → 服务端 → 添加 → 类型 `sing-box` → 协议 `WireGuard`。
- 服务端还需要在防火墙放行 WireGuard 的 UDP 端口；`passwall_server` 默认 `start_delay=90` 秒。
- 这是 **sing-box 的用户态 WireGuard**，不是内核 WireGuard；性能、路由、与 `wg`/`luci-proto-wireguard` 的行为不同，但功能上可作为 WireGuard 服务端/客户端使用。
- 不要把 `wireguard_system_interface` 设为 1：当前没有 `kmod-wireguard`/`wg`，设了会起不来。

### 13.3 如果要原生内核 WireGuard

需要额外安装：

- `kmod-wireguard`（必须与内核 `6.18.55` 完全匹配）
- `wireguard-tools`（提供 `wg`）
- `luci-proto-wireguard`（提供 LuCI 协议）

当前镜像的 opkg 源/签名已被首次启动脚本改坏，且 `kmod-wireguard` 不一定有对应 6.18.55 的包；更稳妥的做法是重新构建固件，或直接用 Passwall + sing-box 的用户态 WireGuard。
